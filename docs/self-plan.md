# 桌宠「自我记忆」计划书

版本：v0.4（2026-11-19）
状态：P1/P2 已实现；多情绪模型 v0.11.0、梦话权重 v0.17.3 已实现；情绪模型误差与 v2 计划见 §16；P3 见 `docs/self-roadmap.md`
关联：`docs/self-roadmap.md`、`docs/mindmap-3d-plan.md`（脑图 3D 化）、`docs/butler-plan.md`、`docs/voice-plan.md`、`SPEC.md`

## 1. 问题

现在的 persona 只记「关于主人的长期事实」。宠物自己的经历、情绪、反思不落盘，跨会话后只剩 dsh-pet 的最近 5 轮聊天记忆，所以它像一个「记得主人的记录工具」，而不是「有连续自我的宠物」。

目标不是让宠物假装有情绪，而是给它一条**可追溯、可衰减、可解释**的自我线：

- 它做过什么（陪主人聊天、被夸奖、被凶、长时间没见）；
- 它现在什么心情（valence / energy，会随时间回落）；
- 偶尔一句自己的反思（P2，可选，不硬造）。

## 2. 非目标

- 不改 dsh-pet 源码，不碰 `whisperPrompt` 与人格所有权。
- 不把自我记忆混进主人事实（`facts.jsonl`），不参与 `主人.*` 的 key 空间。
- 不做“情绪即人格”：注入只提供状态提示，冲突时仍以 dsh-pet 人格为准。
- 不做云同步、不存原声、不记录敏感信息。
- P1 不注入对话；先保证记录与展示不干扰现有功能。

## 3. 数据模型

文件：`<DSH_HOME>/pet-persona/self.jsonl`（追加写，按需压缩）

```json
{"v":1,"id":"s_...","petId":"main","kind":"event","text":"陪主人聊了会儿天","quote":"","valence":0.2,"energy":0.6,"emotions":[{"key":"joy","label":"开心","score":0.46},{"key":"tiredness","label":"疲惫","score":0.5}],"importance":2,"createdAt":"2026-11-18T12:00:00.000Z","hash":"...","source":"chat"}
```

- `kind`: `event`（发生的事）| `feeling`（明确的情绪事件）| `thought`（P2 反思，P1 不产生）
- `text`: ≤80 字，不含敏感信息；命中敏感词时降级为「和主人聊了会儿天」。
- `quote`: 可选原话 ≤60 字，仅当非敏感。
- `valence`: -1..1；`energy`: 0..1。
- `emotions`: 多标签数组，最多 4 项 `{key,label,score}`；8 类为 `joy/affection/sadness/anger/anxiety/tiredness/surprise/calm`，同一句话可同时命中多类。旧记录无此字段时，读取时按 valence/energy 回退。
- 上限 `selfMaxEntries`（默认 500）；超过 1.5 倍时压缩，保留最近 500 条。
- 心情不单独存状态文件，由事件按时间衰减现算，避免状态与事件打架。

## 4. 心情算法（P1 → v0.11.0 多情绪）

### 4.1 单条事件：多标签情绪

`lib/emotion.js` 用轻量词典识别 8 类情绪，不调用模型：

| key | 标签 | 例子 |
| --- | --- | --- |
| joy | 开心 | 开心、好耶、喜欢、终于、来啦 |
| affection | 亲近 | 抱抱、贴贴、想你、亲亲、心疼 |
| sadness | 难过 | 难过、委屈、呜呜、想哭 |
| anger | 生气 | 生气、讨厌、不理我、生气啦 |
| anxiety | 担心 | 担心、紧张、害怕、怎么办 |
| tiredness | 疲惫 | 累、困、熬夜、睡着、没精神 |
| surprise | 惊讶 | 诶、欸、咦、哇、居然 |
| calm | 平静 | 平静、还好、没事、慢慢来 |

- 每个命中给一个权重，最高 1；否定词（不/没/别/无）会跳过该命中；“不开心”会额外加难过分。
- 输出 `emotions`（按分数排序，最多 4 项）、`valence`、`energy`、`mixText`。
- 混合文案：主情绪 + 次情绪（次 ≥ 主 × 0.55）时生成，如“开心但有点累”“又气又委屈”“开心里带点生气”；单情绪时只显示标签。
- 普通闲聊没有命中时落到“平静”，不硬编情绪。

### 4.2 当前心情：按情绪分别聚合

- 对最近 48h 事件做 6h 半衰期加权：`w = 0.5 ** (ageHours / 6) * importance`。
- 每种情绪单独累加 `Σ(w * score)`，再除以“有非平静情绪的事件权重”，避免大量中性记录把情绪稀释成 0。
- “平静”只作为没有任何非平静情绪时的兜底，不参与和开心/生气等竞争。
- 返回前 4 类 `emotions`；`mixText` 用同样规则融合；`valence/energy` 仍保留用于“心情/精力”双条。
- 无事件时：`valence=0, energy=0.5, emotions=[平静]`。

## 5. 写入路径

- 在 `index.js` 的 `capture` 中，`learner.capture(input)` 之后调用 `self.record(input)`；单独 try/catch，失败只记 `self_record_failed`。
- 不同步阻塞回复；内存更新 + 异步 append（串行队列），失败丢弃。
- 跳过：空 userText、纯人格指令（`isPersonaInstruction`）、敏感内容（`sensitiveReason`）。
- 去重：同 petId + 同文本 hash 在 10 分钟内只记一次，避免连续重复。

## 6. 注入（P2，默认关闭）

- 配置 `selfInject` 默认 false；开启后 recall 在记忆块之后追加：

```
【我现在的心情】
开心 · 精神。刚才陪主人聊了会儿天。
```

- 最多 2 行 + 1 条最近事件，独立预算 `selfBudget`（默认 160 字符）。
- 不改变「`system = base + "\n\n" + 记忆块`」的既有契约：没有记忆块时自我块单独作为追加段；有人格冲突时以 dsh-pet 为准。
- 注入失败一律降级为不追加，不影响主人记忆。

## 7. 展示（P1）

设置页第六个 tab「它自己」：

- 顶部心情卡：`mixText`（如“开心里带点生气”）+ 前 4 类情绪徽章（带百分比）+ valence/energy 双条 + 最近更新时间；
- 脑图：以「我」为根，按 8 类情绪分支聚合最近经历，一条经历可落在多个标签里；点圆点看详情；
- 时间线：kind 徽章、多情绪标签、text、原话、时间；空态提示「和它聊几句，它才会慢慢有自己的一天」；
- 刷新按钮；不提供编辑（避免伪造记忆）；提供「清空自我记忆」需二次确认（P1 可只做后端 reset）。

## 16. 情绪判断误差与 v2 计划（2026-11-19）

### 16.1 实测：现在的标签偏在哪

读 `E:\DeepSeek\dsh-home\pet-persona\self.jsonl`（190 条带 `emotions` 的事件）统计：

| 情绪 | 命中事件数 |
| --- | --- |
| 疲惫 tiredness | 80 |
| 平静 calm | 74 |
| 难过 sadness | 31 |
| 惊喜 surprise | 15 |
| 生气 anger | 11 |
| 亲近 affection | 8 |
| 开心 joy | 3 |
| 担心 anxiety | 1 |

抽查后确认这不是「它真的这么累」，而是三类系统性误差：

1. **包装前缀被当成情绪**：所有梦话的 `text` 都是「睡着时说了句梦话：…」，
   `analyzeEmotion` 匹配到「睡着」→ 每条梦话自动 +0.5 疲惫。127 条梦话几乎全部带 tiredness，
   疲惫占比因此长期虚高。
2. **把回复的情绪算成事件的**：`analyzeEmotion(text, replyText)` 直接把主人原话和宠物回复拼在一起。
   例：「在设计你的情绪显示呀」被标 anger 0.46（来自回复里的「哼/坏」）；「确定不困了吗」被标
   tiredness 1（来自回复里的「困」）；「那你先休息吧」被标 surprise 0.36（来自回复的「诶」）。
3. **疑问/否定/称呼被当陈述**：「困就睡吧」「熬夜长不高哦」是主人在说宠物/建议，却被记成宠物疲惫；
   「不困了吗」里的「困」只靠前 1 个字判否定，窗口太窄；「哪怕」「困难」「积累」这类词内字也会误命中。

### 16.2 误差来源清单

| # | 来源 | 例子 | 影响 |
| --- | --- | --- | --- |
| 1 | 子串匹配、无词边界 | 哪怕→怕、困难→困、积累→累、睡衣→睡 | 焦虑/疲惫虚高 |
| 2 | 否定窗口只有前 1 字 | 不是很开心、没有不高兴、并不讨厌 | 否定失效或反向 |
| 3 | 疑问句/询问对方 | 你生气了吗？不困吗？ | 把提问当情绪 |
| 4 | 引号/转述/复读 | 他骂我「滚」& 主人让我滚 | 别人的话算到自己头上 |
| 5 | 主人 vs 宠物通道混在一起 | 回复「抱抱你」→ 亲近；回复「哼」→ 生气 | 事件的标签不是主人的 |
| 6 | 前缀被当正文 | 「睡着时说了句梦话」「陪主人聊了」「主动说了一句」 | 每条都带固定情绪；前缀本身要保留作醒/睡标记，只清洗分析副本 |
| 7 | 无程度词/强度 | 有点累 vs 累死了 vs 还好 | 分数一刀切 |
| 8 | 无上下文 | 上一句在吵架、这一句「嗯」 | 中性回复丢情绪 |
| 9 | 聚合无平滑 | 48h 内只有 2 条事件时直接归一 | 心情大起大落 |
| 10 | 平静是默认兜底 | 没命中就 calm=0.55 | 平静被高估 |

### 16.3 v2 目标

- 让「疲惫/平静」不再因为包装文本和默认兜底虚高。
- 分清「主人的情绪」「它自己的情绪」「它对主人的回应」三个通道，先定义心情看谁。
- 否定、疑问、转述、程度词有明确规则；低置信事件不污染心情。
- 有可复现的评测集和指标，改词典前后能对比，不再靠感觉。

非目标：不做通用情感大模型；不改变现有事件结构（只加字段）。

### 16.4 设计

**A. 通道分离（已拍板：心情 = 宠物自己的情绪）**

```js
analyzeEmotion({ userText, replyText, context })
// → { self: {...}, user: {...}, confidence }
```

- 已拍板（m01741）：心情是**它自己的情绪**，不是主人的。事件可以记录「主人当时说了什么」，
  但主人原话里的难过/生气不能直接变成它的心情。
- `emotions` 只从**它自己的输出**分析：回复、嘟囔、梦话内容、主动说的一句。
- `userEmotions` 单独存主人这句话的情绪，只作为事件背景与详情展示（「主人当时难过」），
  不参与心情聚合、不参与脑图占比。
- 前缀保留、只清洗分析副本：落盘的 `text` 仍保留「睡着时说了句梦话：」「自己嘟囔了一句：」等前缀
  （用来区分醒/睡，旧记录也靠它兼容 `sleeping`）；但送进 `analyzeEmotion` 的是去掉前缀的语音内容，
  避免「睡着」二字自动加疲惫。梦话权重由 `sleeping` 字段（旧记录由前缀判断）决定，不由词表决定。
- 共情回声不算自身情绪：回复里只是复述/安慰主人（「抱抱你」「别难过」「摸摸」）时，
  不继承主人的难过/生气；最多记一点亲近（≤0.25）或直接不记。

**B. 文本预处理**

- 去包装前缀、去引号外层、只保留原话 `quote` 优先。
- 分句：`。！？；` 切分，疑问句单独标记。
- 程度词：有点/稍微 ×0.6，很/好/超/特别 ×1.3，死了/极了 ×1.5。
- 否定窗口扩到前 4 字 + 双重否定计数；`别/不要/不用` 后接情绪词视为安慰，不计自身情绪。
- 疑问句：若含「吗/呢/？」且主语是「你/主人」 → 不计自身情绪，最多记「关心」低分。
- 引号/「」内的话、`他说/她说/主人说` 后的话，默认不计自身。

**C. 词表 v2**

- 词条加边界：`累` 前后不能是「积/计/受」等构词字；`困` 排除「困难/困住」；`怕` 排除「哪怕/恐怕」。
- 一词多义表（睡：睡觉=疲惫；睡衣=无）；同义词表按情绪分组。
- 加 emoji/颜文字映射（😂😭😡🥺😴 等）与英文常用词（lol, sad, tired）。
- 每条命中带 `reason`（命中的词、是否否定、是否疑问），便于调试与用户纠正。

**D. 聚合 v2**

- 每条事件带 `confidence`（0–1）：规则命中明确词=0.9，仅程度弱/上下文推断=0.5，默认平静=0.3。
- 心情聚合只收 `confidence ≥ 0.5` 的事件；低置信保留在时间线但不进心情。
- 贝叶斯平滑：每类先验 0.5 条、权重 0.15，避免 1 条事件占 100%；样本 <5 条时显示「还说不准」。
- 平静改成显式低唤醒：只有「确实没命中 + 语境平静」才算，且不参与彩色占比（保持 v0.16 口径）。

**E. 可选 LLM 兜底（默认关）**

- 触发：规则置信 <0.5、或同句出现相反极性、或含反话标记（呵呵/真行/你可真棒）。
- 输入：单句 + 上一条语境；输出：8 类分数 + confidence 的 JSON；预算 1 次/10 条事件，缓存 24h。
- 失败/超预算回退规则结果；LLM 结果标 `source:'llm'`，不覆盖用户纠正。

**F. 用户纠正**

- 设置页时间线每条可改主情绪；写入 `correctedEmotions`，原规则结果保留（`emotions` 不动）。
- 纠正数据进入评测集，词表迭代以此为准；同一文本再出现时优先用纠正缓存。

### 16.5 评测集与指标

- 从现有 190 条 + 新采 200 条中人工标 250 条，覆盖：普通闲聊、梦话、否定、疑问、转述、反话、混合情绪、中性。
- 指标：每类 precision/recall/F1、macro-F1、`tiredness` 精确率、`calm` 误报率、心情 Top1 与人工标注一致率。
- 基线：当前 v0.11.0 规则；目标：macro-F1 ≥ 0.70，tiredness 精确率 ≥ 0.75，calm 误报率 ≤ 15%。
- 回归：`test/emotion.test.js` 增加上述样例；每次改词表跑评测脚本输出对比表。

### 16.6 里程碑

- M1：剥前缀 + 通道分离（user/reply），修梦话与回复串味；补测试；预计收益最大。
- M2：文本预处理（否定窗口、疑问句、程度词、引号/转述）。
- M3：词表 v2（边界、同义词、emoji/英文）+ reason 字段。
- M4：confidence + 聚合平滑 + 平静显式化。
- M5：评测集与脚本，出基线对比。
- M6：可选 LLM 兜底 + 用户纠正入口。
- M7：真实宿主验证（心情卡、脑图、时间线）后提交。

### 16.7 验收

- A40 梦话文本保留前缀（用于醒/睡区分与旧记录兼容），但情绪分析不因「睡着」二字自动带疲惫。
- A41 回复里的「哼/哼唧/抱抱」不再计入事件情绪；主人说「我好难过」时，它的心情不因此变难过。
- A41b 共情回复「抱抱你/别难过」最多记亲近 ≤0.25，不继承主人的难过/生气。
- A42 「不是很开心」判难过/低开心，不判开心；「哪怕」不判害怕。
- A43 「你生气了吗？」不判生气，最多低分关心。
- A44 「别难过」不给自己加难过。
- A45 只有 1–2 条事件时心情显示「还说不准」，不出现 100% 单情绪。
- A46 250 条评测集上 macro-F1 ≥ 0.70、tiredness 精确率 ≥ 0.75。
- A47 用户纠正一条后，该条后续聚合使用纠正值。

### 16.9 风险

- 改词典会影响历史数据的解读；旧事件不重算，只影响新事件与心情聚合，避免脑图突变。
- 剥前缀后梦话只剩梦话内容，可能更碎；梦话权重已由 0.05/20% 上限控制，不再靠文本标签。
- 通道分离会让「它自己的心情」变少：如果主人很少表达情绪，心情会长期平静；这是真实情况，不应硬编。
- LLM 兜底有成本与隐私问题，默认关、按条触发、可审计。
