# 「它自己」脑图 3D 化计划书

版本：v0.7（2026-11-18）
状态：最终实现为 canvas 手写 3D 网格脑模型（v0.15.x–v0.16.2）：情绪色水铺满脑表面、无融合线、小占比有定位点、平静度单独压暗；代码完成并同步安装副本，待真实宿主视觉验收
关联：`docs/self-plan.md`（v0.11.0 多情绪）、`docs/self-roadmap.md`、`client.js`、`lib/emotion.js`、`lib/emotion-space.js`

## 1. 问题

现在「它自己」的脑图（`client.js:1395` 起）是二维辐射图：

- 8 个情绪分支固定在一个圆周上，每条经历只按**第一情绪**归到一个分支
  （`client.js:1216` 的 `emotionOfEvent` 取 `list[0]`），其余情绪标签只在详情里出现；
- 「开心但累」「又气又委屈」这类混合情绪在图上被拆成单选，**融合关系完全看不见**；
- 所有叶子到圆心的连线长度相同，只表达“属于哪类”，不表达强度、接近程度和时间；
- 每个分支最多 5 条（`slice(0, 5)`），时间一长图就停在最早/最近的一小撮；
- 一个 430px 高的 SVG，128/236 两个半径，事件一多文字就叠在一起。

结论：二维圆周能表达“分类”，表达不了“情绪是连续空间里的点、混合情绪在两类之间”。

## 2. 目标与非目标

### 目标

1. 把情绪从 8 个互斥桶改成**连续的三维情绪空间**，一条经历是空间里的一个点；
2. 一条经历的多情绪得分决定它的位置，天然落在两类情绪的**中间**；
3. 多类共激活且空间上聚在一起的事件，聚成**融合点/融合云**（如“开心 + 疲惫 = 满足的累”），
   点开能看到哪些经历参与了融合；
4. 可拖拽旋转、滚轮缩放、点击查看；保留现有二维图作为回退；
5. 零新增运行时依赖，不碰 `dsh-pet`，不改 recall / 注入 / 主人事实。

### 非目标

- 不引入 three.js / WebGL 库，不做写实渲染；
- 不改情绪识别算法本身（`lib/emotion.js` 的词典与打分保持 v0.11.0）；
- 不把“融合点”当成新事实或新人格写进 `self.jsonl` / `facts.jsonl`；
- 本轮不动「记忆脑图」（主人事实，`client.js:321` 的二维树），只做「它自己」；
- 不做移动端专属布局（先保证桌面设置页可用，触控只做基础支持）。

## 3. 设计原则

1. **位置即含义**：不复用圆周，点与点之间的距离、方向都有解释；
2. **可解释优先于好看**：每个点的来源、每条融合的构成都能点开看到事件 id；
3. **融合是共现，不是断言**：界面注明“融合只表示这些情绪同时出现，不是新的设定”；
4. **渐进增强**：3D 是默认视图，但 2D 一键可回，数据与接口都不依赖 3D；
5. **静态优先**：不跑常驻动画循环，只有拖拽/缩放时才重绘。

## 4. 空间模型：8 锚点情绪球

### 4.1 坐标轴

用三条直觉轴，范围 `[-1, 1]`：

| 轴 | 含义 | 正方向 | 负方向 |
| --- | --- | --- | --- |
| X | 关系取向 | 亲近、想靠近 | 对抗、想推开 |
| Y | 能量 | 有精神、活跃 | 疲惫、低落 |
| Z | 安心感 | 确定、安心 | 不安、警觉 |

「平静」放在原点：没有明显情绪时它就是中心，不参与和别的情绪竞争（与 v0.11.0 的聚合规则一致）。

### 4.2 锚点表（初版，可按真实数据微调）

| 情绪 | x | y | z |
| --- | --- | --- | --- |
| joy 开心 | 0.10 | 0.90 | 0.35 |
| affection 亲近 | 0.85 | 0.35 | 0.25 |
| sadness 难过 | -0.10 | -0.85 | -0.45 |
| anger 生气 | -0.85 | 0.45 | 0.20 |
| anxiety 担心 | -0.20 | 0.15 | -0.90 |
| tiredness 疲惫 | 0.10 | -0.80 | 0.30 |
| surprise 惊讶 | 0.20 | 0.70 | -0.55 |
| calm 平静 | 0 | 0 | 0 |

锚点只做归一化参考；事件位置不吸附到锚点上。

### 4.3 事件位置

每条事件已有 `emotions: [{key, score}]`（v0.11.0 起落盘，旧记录读取时回退）。对事件 e：

```
v(e) = Σ score_i * anchor_i        // 只取 score > 0.08 的项
p(e) = v(e)                        // 到球心的距离 = ||v||，即强度
strength(e) = min(1, ||v(e)||)     // 只用于点的大小/透明度
```

- 单情绪事件落在该锚点方向的射线上，强度越强越靠外；
- 双情绪事件（开心 0.46 + 疲惫 0.50）自然落在两锚点连线中间，这就是“融合”的几何来源；
- 平静/无情绪事件靠近球心，用小灰点表示；
- 为避免同一位置完全重叠，加**确定性抖动**：以 `event.id` 的 hash 生成 ±0.03 的偏移，
  同一数据每次渲染位置一致，便于点选与截图复现。

半径统一乘 0.85，留出标签空间；球心到最外圈的视觉半径约 180px（在 640×540 viewBox 内）。

## 5. 融合点与融合云

### 5.1 判定

一条事件若同时满足，则记入一个“融合对”：

- 两类情绪 `score >= 0.25`；
- 次情绪 `>= 主情绪 * 0.5`（与 v0.11.0 混合文案的阈值一致）。

二元组按 key 排序去重，得到 `fusionPairs`（如 `joy+tiredness`）。

### 5.2 融合命名（初版）

| 组合 | 名称 | 组合 | 名称 |
| --- | --- | --- | --- |
| joy + tiredness | 满足的累 | anger + sadness | 委屈 |
| anxiety + affection | 舍不得 | joy + affection | 甜甜的亲近 |
| sadness + affection | 心疼 | anger + anxiety | 又慌又气 |
| surprise + joy | 惊喜 | tiredness + calm | 放空 |
| anger + tiredness | 烦躁 | sadness + tiredness | 低落 |
| anxiety + surprise | 一惊 | joy + calm | 安心开心 |

未列出的组合走 `blendLabel()` 的“A 里带点 B”句式，不硬造词。

### 5.3 聚合成云

- 同一 `fusionPair` 的事件，若在 3D 空间距离 `< 0.35`、且时间在最近 7 天内，聚成一个融合节点；
- 融合节点位置 = 成员位置加权平均；半径 `r = 10 + 4 * sqrt(count)`，透明光晕 + 实心名字；
- 少于 2 条成员不显示融合节点，避免“一句话就成一团”；
- 融合节点可点击：右侧详情显示成员列表（时间、text、两类得分），并可“只看这一团”过滤时间线；
- 融合节点只存在于渲染层，不写盘、不进入注入块。

## 6. 渲染方案

### 6.1 选型对比

| 方案 | 依赖 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- | --- |
| SVG + 手写透视投影 | 0 | 复用现有 `h('svg')`、DOM 事件现成、文字清晰 | 节点多了重排成本高 | **采用** |
| Canvas 2D 点云 | 0 | 上千点也流畅、辉光好做 | 命中测试、可访问性、文字都要手写 | 二期备选（>300 条时） |
| CSS 3D transform | 0 | 真透视、写起来快 | z 排序/文字朝向/命中都不稳 | 不采用 |
| three.js / WebGL | ~600KB | 效果最好 | 与“零依赖”冲突，Shadow DOM/打包风险 | 不采用 |

### 6.2 投影

```
旋转：先绕 Y 轴 rotY，再绕 X 轴 rotX（默认 rotX=-12°, rotY=18°）
透视：scale = f / (f + z')，f = 520，z' 为相机空间深度
屏幕：sx = x' * scale + cx，sy = y' * scale + cy
排序：按 z' 从远到近绘制（远的小、淡，近的大、实）
```

- 默认视角略微俯视，不自动旋转；`prefers-reduced-motion` 下禁用惯性/回弹；
- 拖拽改 rotX/rotY，限制 rotX ∈ [-75°, 75°]，避免翻转；
- 滚轮缩放改 f 或统一 scale，范围 0.6–2.2；
- 双击/按钮复位。

### 6.3 视觉层级

1. 背景：三条淡轴 + 球心“我”标签，可选显示轴名；
2. 融合云：最底层柔光，避免盖住点；
3. 普通事件点：半径 3–6，颜色取主情绪色，透明度按深度 0.35–1；
4. 当前心情点：一个略大的脉冲圈（静态双环，不做持续动画）；
5. 标签：只给最近 8 条、当前心情和融合节点文字；其余点悬停/点选后显示，
   避免二维图上文字互压的问题；
6. 详情面板沿用现有 `selected` 卡片，不新增路由。

## 7. 交互与可访问性

- 拖拽旋转、滚轮缩放、双击复位、`R` 键复位、方向键微调视角；
- 图例：8 类色块 + “融合云”说明；
- 视图切换：「3D 球 / 平面 2D」，2D 即现有辐射图，保留不删；
- 无障碍回退：3D 下方保留“列表”入口（现有时间线），并为每个点提供可聚焦按钮/`aria-label`；
- 触控：单指拖拽旋转，双指缩放（`touch-action: none` 只作用于画布区）；
- 性能：默认只渲染最近 200 条，超过时提示“只显示最近 200 条”；
  拖拽中只更新 `transform`/重投影，松手后一次性重排。

## 8. 数据与接口

- 本轮**不改后端**：`GET /pet-persona/api/self?pet=main&limit=…` 已返回 `events[].emotions`；
- 位置、融合、投影全部在客户端纯函数里算，`self.jsonl` 与 `/self/state` 不变；
- 若以后事件量 >500 或需要跨端一致，再加 `GET /self/graph`，把布局结果放后端；

  避免为纯展示改动 `normalizeConfig` 与设置接口。

## 15. 脑区改版（v0.5，已被 §16 真 3D 取代）

用户看完 3D 球后的要求（m00415/m00418）：主图不要展示对话，只展示每种情绪的占比；
情绪不是孤立的，会互相接壤、融合；点击某一种情绪时显示这类情绪的对话；
希望像真正的大脑，让情绪落在真实脑区。v0.5 进一步明确：脑壳是一个容器，
情绪像水一样**填满整个脑壳**，只是水有不同颜色，交界处只轻微相融、不会完全混成一色。

- 脑壳：`client.js` 的 `BRAIN_PATH`（风格化侧视轮廓，含额叶/顶叶/颞叶/枕叶起伏）+
  `BRAIN_CEREBELLUM` 小脑椭圆 + `BRAIN_STEM` 脑干，三者组成 `clipPath`。
- 填满：不再画悬浮色块。以 8 个 `BRAIN_REGIONS` 投影点为站点，做**加权 Voronoi**
  （权重 `share * 90000`，半平面裁剪），每个情绪分到一块领地，并集覆盖整个脑壳；
  面积为占比的近似（Voronoi 面积与权重非线性，3% 以下会很小）。
- 不完全融合：整组色块加 `feGaussianBlur 3` 柔化边界，色块之间不做透明叠加，
  所以交界是「两种颜色的水贴在一起」而不是混成一色。
- 立体感：每块用 `radialGradient`（userSpaceOnUse，中心在站点）+ 暗角 + 左上高光 +
  4 条低透明度脑回曲线；脑壳、小脑、脑干再描一圈淡色轮廓。
- 点击：色块本身可点，选中后白色描边并在站点显示「名字 百分比」；下方图例按钮同样可点。
  主图下方列出该类情绪相关度最高的 8 条经历（text + quote + 时间 + 相关度）。
- 融合：v0.15.3 起 3D 主图不再画融合虚线与融合云；一条多情绪经历在统计时已分别计入各情绪占比，主图只展示单情绪领地。
- 平静双轨：彩色领地仍按非平静归一；另算 `calmRatio = calmSum / (calmSum + 非平静权重)`，作为「平静度」徽章显示，并在 3D 画面上蒙一层灰（alpha 0.12–0.42），平静越高整体越淡。
- 极小情绪：3D 领地按 `max(share, 0.05)` 加权（标签仍显示真实占比），占比 <5% 的情绪（如担心 3%）另画一个同色小圆点 + 名字定位，保证找得到。
- 保留 3D/2D 切换；2D 仍是事件辐射图，未改。
- 平静作为底色，不参与占比；只有全是平静时才显示 calm。
- 未做：真实脑回纹理、领地内部的流动动画、左右半球成对色块；脑壳是风格化侧视，不是解剖模型。
- 数据核查（57 条经历）：tiredness 44%、surprise 17%、anger 16%、affection 11%、
  joy 9%、anxiety 3%。

> 本节的 SVG 加权 Voronoi 是过渡方案；v0.15.0 起由 §16 的 canvas 3D 网格取代。
> `BRAIN_PATH`/`BRAIN_STEM`/`voronoiCells` 仍留在 `client.js` 里但不再被渲染，可在下轮清理。

## 16. 最终实现：canvas 3D 网格脑模型（v0.15.0–v0.16.2）

v0.5 的 SVG 色水是平面投影，拖拽只是移动色块、没有体积感。M6 改为 canvas 手写 3D，
M7 补平静双轨；最终版本如下（以 `client.js` 为准）：

### 网格与形状
- `buildBrain3D()` 生成三块球面网格：主脑 `rx=1.04R, ry=0.82R, rz=1.14R`（76×132 面）、
  小脑（22×34，固定底部后方）、脑干（16×22）；`BRAIN3D_FACES` 预计算每面世界法线与质心。
- 主脑半径叠加颞叶隆起 + 多组正弦脑回 + 深沟项；着色再乘 11u 正弦明暗沟。
- 小脑与脑干固定用疲惫色（占比里通常最大）。

### 颜色与占比
- 每面按质心方向与 8 个锚点方向的角距 `angle`，`score=(angle+wobble)^2 - 10*max(share,0.05)` 取最小；
  `wobble` 让领地边界不规则；面积是占比的近似，不是严格等面积。
- 占比口径（v0.16.2 恢复）：**全部经历**里 score>0.08 的非平静情绪得分归一，
  与「最近的心情」文字独立；当前 70 条：疲惫 44.8%、生气 19.2%、惊讶 15.1%、
  亲近 10.0%、开心 8.2%、担心 2.6%。
- 平静不计入彩色占比；`calmRatio` 由客户端按 48h/6h 半衰现算，当前 59.7%，
  作为「平静度」徽章并把 3D 画面整体蒙灰（alpha 0.12–0.42）。
- 占比 <5% 的情绪：权重抬到 5% 保证有领地，并在站点画圆点 + 「名字 x%」。

### 渲染与交互
- 光照：lambert（L=(-0.36,0.72,0.6)）+ 边缘光 + 高光 + 沟壑明暗；不剔除背面，
  按 depth 升序全量绘制（背面先画、正面后盖），同色描边盖缝，避免漏黑底与接缝。
- 拖拽改 rotX/rotY（clamp ±75），滚轮缩放 0.55–2.4，双击/按钮复位。
- 点击：倒序遍历可见面做多边形命中，选中面提亮并显示「名字 百分比」；图例按钮同样可点。
- 主图下方列该类情绪相关度最高的 8 条对话（text + quote + 时间），画布上不出现对话文字。
- 性能：约 1 万面，单次绘制；只在 view/mapMode/camera/selectedEmotion/events 变化时重绘。
- 3D 为默认，2D 辐射图保留；偏好写 `localStorage['dsh-pet-persona.selfMapMode']`。

### 未做 / 已知限制
- 领地面积与占比只是近似（角距加权 Voronoi 的固有偏差）。
- 网格仍是风格化椭球 + 正弦脑回，不是解剖扫描网格；未做法线插值平滑。
- 未做领地内部流动动画、左右半球成对色块、移动端手势。
- 3D 主图不再显示融合；融合只在统计上体现。
